# მსჯელობის დონის შედარება

მიზანია დადგინდეს, სად ამართლებს დამატებითი დრო და ხარჯი უკეთეს შედეგს. შედარება იყენებს მხოლოდ `gpt-6.1-sol`-ს, `low`, `medium` და `high` დონეებით. მოდელი, ინსტრუქციები, შემავალი მონაცემები, შემოწმებები, 10,000 გამომავალი ტოკენის ზღვარი და 150-წამიანი მოთხოვნის ლიმიტი ყველა დონეზე ერთნაირია. პარამეტრები გადამოწმებულია [მოდელის ოფიციალურ დოკუმენტაციაში](https://developers.openai.com/api/docs/models/gpt-6.1-sol).

რვა განსხვავებული მაგალითი ორჯერ მეორდება თითო დონეზე: ბრენდის გააზრება, სტრატეგიის გადახედვა, პოსტების გეგმა, ფასის ტექსტი, პოლიტიკური ხმის ტექსტი და სამი შემოწმება — სწორი ფასი, მცდარი ფასი, სწორი ფორმატით დაწერილი ხმადაკარგული ტექსტი. სულ დაგეგმილია 48 შედეგი და მინიმუმ 66 API მოთხოვნა; პოსტების შემოწმება ორ დამოუკიდებელ მოდელის მოთხოვნას იყენებს. გაშვების რიგი მონაცვლეობს მაგალითისა და გამეორების მიხედვით.

ეს კონტროლირებადი მონაცემებია. ახალი სარედაქციო მაგალითი ხელოვნურადაა შექმნილი და მომხმარებლის ძველ რეალურ ტექსტად არ უნდა წარმოდგეს. სტრატეგიის მაგალითიც სინთეზურ საჯარო ამონაწერს იყენებს. არც ერთი მაგალითი არ კითხულობს წარმოების ბაზას, არ აქვეყნებს პოსტს და არ ცვლის მომხმარებლის მონაცემებს. ძირითადი მაგალითების მიმდინარე აპლიკაციის ფუნქციები უცვლელი ინსტრუქციებით სრულდება; სტრატეგია იყენებს worker-ის იმავე prompt/schema/validator კონტრაქტს, წყაროსა და ბაზასთან მუშაობის გარეშე.

ყველა API მცდელობას აქვს ერთი საერთო ბიუჯეტი: მაქსიმუმ 80 მოთხოვნა, 3,000,000 მოთხოვნის ბაიტი, 150,000 გამომავალი ტოკენი, 30 წუთი შესრულება და $3 კონსერვატიულად შეფასებული API ხარჯი. ეს ექსპერიმენტის ზღვარია და კომპანიის თვიური ხარჯის გარანტია არ არის. დაშვებისას დაჯავშნილია მოთხოვნის მაქსიმალური სავარაუდო ღირებულება; პარალელური მოთხოვნები, უცნობი გამოყენება და ჩავარდნები ბიუჯეტს არ აღადგენენ. ფასში ქეშის წაკითხვა და ჩაწერა ცალ-ცალკე ითვლება; მსჯელობის ტოკენები გამომავალი ტოკენების შემადგენლობაში ერთხელაა დათვლილი. გათვლა არ არის ანგარიშფაქტურა.

კონკრეტული მოთხოვნების კონტროლი ცალკე ითვლება. თითო მაგალითის ოთხი თვისებრივი კრიტერიუმი პასუხების მიღებამდე ინახება manifest-ში. შემდეგ შეფასდება ტექსტის კონკრეტულობა, ბრენდის ხმა, არგუმენტის განვითარება, წყაროს დაცვა, გეგმის შესრულებადობა და სარედაქციო შენიშვნის სიზუსტე. მკაცრი მოთხოვნის დარღვევა ვერ ანაზღაურდება უფრო ლამაზი ტექსტით. პასუხის სიგრძე ან მოდელის საკუთარი შეფასება ხარისხის გაუმჯობესების მტკიცებულებად არ ჩაითვლება.

შემდგომი წაკითხვა ასისტენტის თვისებრივი შეფასება იქნება. პასუხების სანახავ ფაილებში დონე და დრო დაიფარება, თუმცა ეს დამოუკიდებელი ადამიანური შეფასება არ არის და საბოლოო მტკიცებულებაში ამ განსხვავებას შევინარჩუნებთ. ორი გამეორება რეალური ტრაფიკის წარმომადგენლობით ან სტატისტიკურად სანდო ხარისხის კვლევად არ ჩაითვლება.

შერჩევისას გავითვალისწინებთ ორივე გამეორების კონკრეტული მოთხოვნების შესრულებას, თვისებრივ სარგებელს, განმეორებებს, შეწყვეტილ პასუხებსა და დროის ზრდას. დაუდასტურებელი სარგებლის შემთხვევაში `high` ავტომატურად არ ჩაირთვება. ბრენდისა და სტრატეგიის საფუძველს უფრო მაღალი პრიორიტეტი აქვს, რადგან მათი გადაწყვეტილებები შემდგომ პოსტებზე მოქმედებს. ინტერაქტიული მითითებების არსებული 40-წამიანი და შესწორების შემოწმების 60-წამიანი გზები ამ ექსპერიმენტში არ იზომება; მათი ლიმიტების შეცვლა ცალკე მტკიცებულებას საჭიროებს.

ძირითადი შედეგები და გამოყენების ჩანაწერები შეინახება `.local/reasoning-comparison/live-01/`-ში. გაყინული ანაბეჭდები დაიცავს საწყის პირობებს. ექსპერიმენტი სამუშაო კონფიგურაციას ავტომატურად არ ცვლის.
