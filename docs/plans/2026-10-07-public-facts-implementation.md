# მეორე ეტაპი — დადასტურებული ფაქტები და წყაროს დასტური

იმპლემენტაციის თარიღი: 7 ოქტომბერი, 2026. საფუძველი: [T04-ის გეგმა](./2026-10-06-implementation-plan.md). წინა პაკეტის მდგომარეობა შენარჩუნებულია; ცვლილების დაწყებამდე შესაბამისი ფაილების ანაბეჭდები აღრიცხულია [საწყის ჩანაწერში](./2026-10-07-public-facts-baseline.json).

## დასრულებული სამუშაო

- ბრენდის გვერდზე მომხმარებელი ამატებს და განაახლებს შეთავაზებას, ფასს, კონტაქტს, საათებსა და ხელმისაწვდომობას. თითოეულ ჩანაწერს აქვს აშკარა დადასტურება, ავტორი, მოქმედების ვადა და გამოყენების ნებართვა. შესაძლებელია გამოყენების შეჩერება.
- გამოყენებულია ძირითადი პროგრამის `BusinessFact`, `FounderDecision`, `Proof`, `ProofAssessment` და `GenerationPermission` ტიპები. რეესტრი ინახავს მიმდინარე ვერსიას და ცვლილების ისტორიას. ერთ ბრენდში ერთნაირი ტიპის/თემის მეორე ჩანაწერი კონფლიქტია; განახლება მოწმდება ვერსიით. გამეორებული მოთხოვნა ცვლილებას მეორედ არ ასრულებს.
- წყაროს დასტური ეხება მხოლოდ მომხმარებლის მიერ დადასტურებულ ზუსტ ციტატას. წყარო მოდის იმავე ბრენდის შენახული Evidence/Snapshot-იდან; დასტური მოითხოვს ცალკე დადასტურებას აქტუალურობისა და საჯარო გამოყენების უფლების შესახებ. უცნობი, არასაკმარისი, უცხო ბრენდის, შიდა ან ვადაგასული დასტური საჯარო ავტორიტეტს ვერ იძლევა.
- ახალი კვირის გეგმა ინახავს რეესტრის უცვლელ snapshot-ს. დაგეგმვა არჩევს პოსტისთვის საჭირო ნებადართულ ფაქტებს; ტექსტის შემქმნელი და ფაქტობრივი შემფასებელი იღებს ამავე პოსტისთვის შერჩეულ ვერსიას. შიდა ინფორმაცია ცალკე რჩება. სარედაქციო შემფასებელი საჯარო ფაქტის ახალი ავტორიტეტი ვერ ხდება.
- ტექსტთან ინახება გამოყენებული fact/proof მითითებები, ხოლო წყაროს Evidence ID უკავშირდება publication-ის კანონიკურ brief-ს. შეფასების ანაბეჭდი მოიცავს factual snapshot-საც. review-ში სხვა snapshot-ის ჩასმა ძველ დამტკიცებას ვერ გამოიყენებს.
- ხელახალი დამტკიცება, განრიგის შენახვა, რიგიდან არჩევა და გაგზავნის დაწყების დაფიქსირება ამოწმებს ფაქტის მიმდინარე ვერსიას, ნებართვასა და ვადას. შერჩეული ფაქტები მოწმდება მაშინაც, თუ ტექსტის შემქმნელმა გამოყენების მითითება გამოტოვა. შეუსაბამო პოსტი შეჩერდება და მომხმარებელი კონკრეტულ მიზეზს დაინახავს.
- შეჩერებული immutable publication input შემდეგ ციკლში რიგიდან გამოირიცხება. სხვა პოსტები დამუშავებას აგრძელებს. უკვე დადასტურებული ან გაურკვეველი გარე გამოქვეყნების შედეგი ფაქტის შეჩერებით არ იშლება.
- რაოდენობის ცვლილება ინარჩუნებს დარჩენილი ტექსტების ფაქტების მითითებებს. გვერდის მსუბუქი სტატუსი რეესტრის ცვლილებას და ვადის გასვლასაც ითვალისწინებს.

## წესების საზღვრები

ფასს, საათებსა და ხელმისაწვდომობას მომხმარებელი ადასტურებს მაქსიმუმ 90 დღით, შეთავაზებასა და კონტაქტს — 365 დღით. ბრენდზე რეესტრის ზღვარია 100 ჩანაწერი, დღეში მომხმარებელზე — 200 ცვლილება. ეს არის ვიწრო, ხელით დადასტურებული ბიზნესფაქტების რეესტრი.

წყაროს დასტურის პოლიტიკაა `owner-verbatim-source-v1`: იგი არ წარმოადგენს დამოუკიდებელ კვლევას, მიზეზობრივი ეფექტის ან შედეგის გარანტიას. ტექსტში ყველა კონკრეტული მტკიცების შესაბამისობა კვლავ რეალური მოდელის factual review-ით მოწმდება; მითითებების პროგრამული კონტროლი სემანტიკური სიზუსტის სრულ გარანტიას არ იძლევა.

Discovery-ის ინტერპრეტაციები ავტომატურად არ გარდაიქმნება საჯარო ფაქტებად. ძველი V1 publication bundle-ები იკითხება არსებული compatibility წესით; მათთვის ახალი დადასტურება ან factual snapshot არ გამოიგონება. შეცვლილი ფაქტი ძველი დამტკიცებული ტექსტის ავტომატურ გადაკეთებას არ იწვევს — საჭიროა ახალი განხილვა და დამტკიცება.

## გაშვების წინ

დამატებულია ადიტიური მიგრაცია `0020_public_knowledge.sql`. აპლიკაციისა და worker-ის ამ ვერსიის გაშვებამდე ის უნდა შესრულდეს შესაბამის გარემოში. ამ სამუშაოში მიგრაციები შესრულდა მხოლოდ ტესტების იზოლირებულ დროებით სქემებში; მოქმედი გარემოს მონაცემები არ შეცვლილა.

ავტორიზებულ ცოცხალ ინტერფეისში საბოლოო UX შემოწმება და საწარმოო rollout კვლავ ცალკე ოპერაციული ნაბიჯია. რეალური სოციალური გამოქვეყნება და ფასიანი მოდელის გამოძახება არ განხორციელებულა; Jev გამორთულია.
